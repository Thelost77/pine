# pine and spruce v0.10.0

This release adds a library scan to the command palette of pine. pine starts a
scan of the library on the server, waits for the end of the scan, and then
loads the lists again. spruce has no change.

## Installation

```sh
go install github.com/Thelost77/pine@v0.10.0
go install github.com/Thelost77/pine/cmd/spruce@v0.10.0
```

As an alternative, download an archive from the release page. See "Binaries".

## Binaries

The release has one archive for each program and each system. The name of an
archive is `<program>_v0.10.0_<system>_<architecture>`:

| System | Architecture | File type |
|--------|--------------|-----------|
| `linux` | `amd64`, `arm64` | `.tar.gz` |
| `darwin` (macOS) | `amd64`, `arm64` | `.tar.gz` |
| `windows` | `amd64` | `.zip` |

Each archive contains the program, the `LICENSE` file of pine, and a `licenses`
directory. That directory has the license texts of Go and of the modules that
the program links.

- A binary needs libmpv. See "Requirements".
- On Windows, put `libmpv-2.dll` in the directory of the program. The archive
  does not contain it.
- The binaries are not signed.
- A GitHub Actions workflow builds the binaries on Linux with `CGO_ENABLED=0`.
  No binary of this release has run on a test machine.

## pine

### New Features

* **The command palette has the new entry "Scan Library".** It is in the
  group "Library". pine starts a scan of the library of the current screen on
  the server, with `POST /api/libraries/{id}/scan`.
* **pine loads the lists again after the end of the scan.** The server answers
  the scan request before the scan. pine reads the scan time of the library
  (`lastScan` of `GET /api/libraries/{id}`) every 2 seconds until it changes.
  Then pine clears its cache and loads the home screen and the library screen
  again. The new books show at once, and pine does not show an old list from
  its cache.
* Use the scan when the server did not find new books itself. For example, a
  server in a container can get no file event for a folder that a program
  copies into the library.

### Limits

* Only an admin user can scan a library. For a different user, pine shows the
  error `ABS user does not have the admin permission to scan` in the error
  banner.
* pine shows no progress while the scan runs. The lists load again when the
  scan ends.
* pine waits for the end of the scan for 30 minutes at most. After that time,
  pine shows an error and does not load the lists again.
* The server changes `lastScan` only after a complete scan. If a scan does not
  complete, pine waits until the 30 minutes end.

## spruce

spruce has no change in this release. The shared package
`internal/ui/components` has one new palette action, which only pine uses.

## Development

* "Scan Library" has an end-to-end test with a fake Audiobookshelf server and
  the mock player of the app tests. The test failed when the reload after the
  scan was removed.
* `abs.ScanLibrary` has tests for the wait, for the end of the context, and
  for a refused scan. The cache client has a test that it clears the cache
  only after a scan that ended.
* On macOS, `gofmt`, `go vet`, and the tests with `PINE_REQUIRE_LIBMPV=1` and
  `PINE_REQUIRE_DBUS=1` passed. `golangci-lint` 2.14.0 did not run on the
  development machine. The CI workflow runs it on the push to `main`.
* No check ran against a real server. grove-server has the scan route and the
  `lastScan` field, and translates them from Audiobookshelf 2.37.1 (`scan` in
  `server/controllers/LibraryController.js` and in
  `server/scanner/LibraryScanner.js`).
* The dependencies have no change.

## Requirements

- Go 1.26.4 or newer, for an installation from source
- libmpv from [mpv](https://mpv.io/) 0.34 or later
- pine: an [Audiobookshelf](https://www.audiobookshelf.org/) server
- spruce: a [Jellyfin](https://jellyfin.org/) account with a music library
