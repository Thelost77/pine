# pine and spruce v0.11.0

This release makes the command palette of pine use the correct library, and it
shows the true state of the server in more places. The palette has a new entry
that loads all data again, the search shows the results of each library, and a
box shows while a scan runs. spruce has no change.

## Installation

```sh
go install github.com/Thelost77/pine@v0.11.0
go install github.com/Thelost77/pine/cmd/spruce@v0.11.0
```

As an alternative, download an archive from the release page. See "Binaries".

## Binaries

The release has one archive for each program and each system. The name of an
archive is `<program>_v0.11.0_<system>_<architecture>`:

| System | Architecture | File type |
|--------|--------------|-----------|
| `linux` | `amd64`, `arm64` | `.tar.gz` |
| `darwin` (macOS) | `amd64`, `arm64` | `.tar.gz` |
| `windows` | `amd64` | `.zip` |

Each archive contains the program, the `LICENSE` file of pine, and a `licenses`
directory. That directory has the license texts of Go and of the modules that
the program links.

- A binary needs libmpv. See "Requirements".
- On Windows, put `libmpv-2.dll` in the directory of the program. The archive
  does not contain it.
- The binaries are not signed.
- A GitHub Actions workflow builds the binaries on Linux with `CGO_ENABLED=0`.
  No binary of this release has run on a test machine.

## pine

### New Features

* **The command palette has the new entry "Refresh".** It is in the group
  "Library". pine clears its local cache, then loads the screens and the
  library list again. It starts no scan on the server, and it needs no admin
  permission. Use it after a change in the web UI of the server, for example
  a metadata edit or a new library.
* **The palette search shows the results of each library.** The results of the
  library of the current screen are first. The results of each other library
  are below a header with the name of that library. Before, a search for a
  book gave no result while the home screen showed the podcast library.
* **The palette shows when a search index is not ready.** The row
  `Building index…` is the last row until pine has the index of each library.
  pine builds the indexes in the background after the start.
* **A box shows while a scan runs.** The box is at the top right, with a
  spinner and the text "Scanning", followed by the name of the library. pine
  stays usable during the scan. The box goes away when the scan ends.
* **The scan entry shows its library.** The entry is `Scan Library: <name>`.
  While a scan runs, the entry does nothing.
* **"Browse Series" is available on each screen of a book library.** The entry
  is in the group "Navigation" on the home screen, the library screen, the
  detail screen, the series screen, and the sessions screen of an item. It
  opens the series of the library of that screen.
* **The series list shows the number of books of each series.** The list is
  also in name order. Before, the server gave the series in no defined order.

### Fixes

* **"Go Series List" opened a series list for a podcast library.** The entry
  used the library of the home screen and did not check its type. A podcast
  library has no series. "Browse Series" replaces the entry, and it shows only
  for a book library.
* **"Go Library" opened the wrong library.** It opened the first library of the
  server, or the library that the library screen showed last. It now opens the
  library of the current screen.
* **An open screen kept its old data after a scan.** Only the home screen and
  the library screen loaded again. The open series list, series screen, and
  detail screen of the scanned library now load again too.
* **pine could hide a library that has audiobooks.** pine read only the first
  10 items of a book library. A library that starts with ebooks, or an empty
  library, was not in the library list for 24 hours. pine now reads the item
  with the longest duration. It hides a book library only when the library has
  items and none has audio.
* **On the sessions screen of an item, the palette used the library of the
  home screen.** "Scan Library" and the search then used a different library.
  They now use the library of the item.
* **On the series screen, the palette search used the library of the home
  screen.** It now uses the library of the series.
* **The palette moved the highlight to the first result when a search index
  became ready.** The highlighted result now stays highlighted.
* **An answer of an earlier load could replace newer data.** This was possible
  on the home screen, in the series list, and on the series screen. Each load
  now has an ID, and a screen drops the answer of an earlier load.

### Limits

* After the update, pine fetches each cached value one more time. The type of
  a cached value changed, so pine does not read the old cache rows.
* The scan box shows that a scan runs. It shows no progress.
* If the build of a search index fails, for example with no network, the row
  `Building index…` stays. Each key press in the search starts a new build.
* If a bookmark title edit starts while pine loads the bookmarks again, the
  answer closes the editor. pine does not start that load during an edit.
* The sessions of all items have no library. The palette uses the library of
  the home screen there.

## spruce

spruce has no change in this release. The shared package
`internal/ui/components` has one new palette action and one palette action
less, and only pine uses them. `Palette.Refresh` of that package keeps the
selected item. spruce does not call it.

## Development

* The changes are in
  [pull request 18, "Fix seven UX problems in the palette, the scan, and the series list"](https://github.com/Thelost77/pine/pull/18),
  and in one commit before it, `12ed355` (fix(palette): browse series only in
  book libraries).
* A code review of that pull request found six defects in the new reload
  code. Each defect has its own commit and a test.
* Each change has a test that failed before the change. The end-to-end tests
  use a fake Audiobookshelf server and the mock player of the app tests.
* On Linux, `gofmt`, `go vet`, `golangci-lint` 2.14.0, and the tests with
  `PINE_REQUIRE_LIBMPV=1` and `PINE_REQUIRE_DBUS=1` passed. The CI workflow
  passed for the pull request on Ubuntu, macOS, and Windows.
* The sort of the series list (`sort=name`) and the sort of the items by
  duration (`sort=media.duration` with `desc=1`) come from the source of
  Audiobookshelf: `server/controllers/LibraryController.js`,
  `server/utils/queries/seriesFilters.js`, and
  `server/utils/queries/libraryItemsBookFilters.js`. The `books` array of a
  series was seen in the answer of a real server. These notes record no test
  of the two sort parameters against a real server.
* The dependencies have no change. The spinner of the scan box is in
  `bubbles`, which pine already used.

## Requirements

- Go 1.26.4 or newer, for an installation from source
- libmpv from [mpv](https://mpv.io/) 0.34 or later
- pine: an [Audiobookshelf](https://www.audiobookshelf.org/) server
- spruce: a [Jellyfin](https://jellyfin.org/) account with a music library
