# pine and spruce v0.9.2

This release corrects the error report of spruce for a track that does not
load. It adds no feature. pine has no change of behavior.

## Installation

```sh
go install github.com/Thelost77/pine@v0.9.2
go install github.com/Thelost77/pine/cmd/spruce@v0.9.2
```

As an alternative, download an archive from the release page. See "Binaries".

## Binaries

The release has one archive for each program and each system. The name of an
archive is `<program>_v0.9.2_<system>_<architecture>`:

| System | Architecture | File type |
|--------|--------------|-----------|
| `linux` | `amd64`, `arm64` | `.tar.gz` |
| `darwin` (macOS) | `amd64`, `arm64` | `.tar.gz` |
| `windows` | `amd64` | `.zip` |

Each archive contains the program, the `LICENSE` file of pine, and a `licenses`
directory. That directory has the license texts of Go and of the modules that
the program links.

- A binary needs libmpv. See "Requirements".
- On Windows, put `libmpv-2.dll` in the directory of the program. The archive
  does not contain it.
- The binaries are not signed.
- A GitHub Actions workflow builds the binaries on Linux with `CGO_ENABLED=0`.
  No binary of this release has run on a test machine.

## spruce

### Reliability and Correctness

* **spruce showed no error for a track that did not load.** mpv stopped the
  track with an error, but the player did not give the error to spruce.
  spruce stopped the playback and showed no banner. spruce now shows the error
  of mpv in the error banner, for example `play file: loading failed`.
* **spruce wrote a warning to the log two times each second while mpv opened
  a file.** The warning did not give a cause. spruce no longer writes it. The
  player writes the same error at the Debug level, as before.

### Changes of Behavior

* The server can accept the request for a track and then send no data. In
  that case, mpv waits 60 seconds before it stops the track. This is the
  default `network-timeout` of mpv. spruce shows the error banner after that
  time. Before that time, the player footer shows the track as playing.

## pine

pine has no change of behavior in this release. The changed player package is
shared, but pine does not read the end message of the player. In the log, the
warning `mpv failed to play the file` now has `play file: ` before the error
text of mpv.

## Development

* The test `TestMpvLoadFailureGivesErrorAndClosesThePlayer` now requires the
  error of mpv. The test failed before the correction.
* On Linux, `gofmt`, `go vet`, `golangci-lint` 2.14.0, and the tests with
  `PINE_REQUIRE_LIBMPV=1` and `PINE_REQUIRE_DBUS=1` passed.
* mpv 0.37 played from a local HTTP server that sent no reply. After 60
  seconds, mpv wrote `Failed to open <url>.` and stopped.
* spruce did not run against a real Jellyfin server for this correction.
* The dependencies have no change.

## Requirements

- Go 1.26.4 or newer, for an installation from source
- libmpv from [mpv](https://mpv.io/) 0.34 or later
- pine: an [Audiobookshelf](https://www.audiobookshelf.org/) server
- spruce: a [Jellyfin](https://jellyfin.org/) account with a music library
