# pine and spruce v0.7.0

pine and spruce now play audio through libmpv, which they load into their own
process. Before, the two programs started the `mpv` program and controlled it
through a socket.

This release changes the requirement. Install libmpv before you upgrade. See
"Upgrade".

## Installation

```sh
go install github.com/Thelost77/pine@v0.7.0
go install github.com/Thelost77/pine/cmd/spruce@v0.7.0
```

## Upgrade

The two programs need libmpv from mpv 0.34 or later. The `mpv` program is not
necessary.

- Debian and Ubuntu: `sudo apt install libmpv2`. On Ubuntu 22.04 the package is
  `libmpv1`.
- Arch: `sudo pacman -S mpv`
- macOS: `brew install mpv`

If libmpv is absent, the program starts. The first playback then shows an error
that names the package to install.

The two programs do not load the mpv config files. The options in `mpv.conf` do
not apply. With v0.6.0, the `mpv` program applied them.

## pine and spruce

### What's New

* **Playback in the app process:** there is no mpv process, no IPC socket, and
  no temp file for the HTTP headers.
* **Faster start:** the player does not start a process and wait for its
  socket. On the test machine, the start of the player went from more than
  100 ms to about 15 ms.
* **mpv messages in the log:** the warnings and errors of mpv go to the app
  log. The log shows why a stream did not load, for example
  `HTTP error 404 Not Found`.

### Reliability and Correctness

* The two programs find the end of a track through a typed player state.
  Before, pine compared the text of an error message.
* A stream that fails to load does not start `yt-dlp`.
* On macOS, the player sends stereo audio to the output. On a test machine
  with macOS 27.0 and mpv 0.41.0, mono audio played at double speed. The `mpv`
  program has the same fault there, so v0.6.0 has it too. Audio with more than
  two channels is mixed down to stereo on macOS.

### Security

* The library search on Windows and macOS does not include the current
  directory.
* The app log does not contain the query of a stream URL, because a query can
  hold a token.

## Platforms

* **Linux:** tested with mpv 0.34.1, 0.35.1, 0.37.0, and 0.41.0.
* **macOS:** tested on Apple Silicon and on Intel, with mpv from Homebrew.
* **Windows:** the tests pass with `libmpv-2.dll` in the directory of the
  program. The two programs have not run on a Windows machine.
* **FreeBSD:** a build with `CGO_ENABLED=0` fails.

## Development

* A GitHub Actions workflow runs `go vet`, `golangci-lint`, and the tests on
  Linux, macOS, and Windows.
* A Linux build with `CGO_ENABLED=0` is now dynamically linked.

## Requirements

- Go 1.26.4 or newer
- libmpv from [mpv](https://mpv.io/) 0.34 or later
- pine: an [Audiobookshelf](https://www.audiobookshelf.org/) server
- spruce: a [Jellyfin](https://jellyfin.org/) account with a music library
