# pine and spruce v0.9.0

This release adds the listening sessions to pine. A list shows where each
device stopped in a book or a podcast episode, and Enter plays from that
position. The release also corrects the error `unexpected cache miss`, which
stopped a screen or the session restore at times. spruce has no change.

## Installation

```sh
go install github.com/Thelost77/pine@v0.9.0
go install github.com/Thelost77/pine/cmd/spruce@v0.9.0
```

As an alternative, download an archive from the release page. See "Binaries".

## Binaries

The release has one archive for each program and each system. The name of an
archive is `<program>_v0.9.0_<system>_<architecture>`:

| System | Architecture | File type |
|--------|--------------|-----------|
| `linux` | `amd64`, `arm64` | `.tar.gz` |
| `darwin` (macOS) | `amd64`, `arm64` | `.tar.gz` |
| `windows` | `amd64` | `.zip` |

Each archive contains the program, the `LICENSE` file of pine, and a `licenses`
directory. That directory has the license texts of Go and of the modules that
the program links.

- A binary needs libmpv. See "Requirements".
- On Windows, put `libmpv-2.dll` in the directory of the program. The archive
  does not contain it.
- The binaries are not signed.
- A GitHub Actions workflow builds the binaries on Linux with `CGO_ENABLED=0`.
  No binary of this release has run on a test machine.

## pine

### New Features

Listening sessions:

* **The server keeps the last progress that a device sends.** A device with
  an old position can replace a newer position from a different device. The
  listening sessions of the server show where each device stopped. pine now
  shows these sessions, and plays from them.
* **The key `R` opens the listening sessions.**
  * On the detail screen, `R` shows the sessions of the book, or of the
    podcast episode under the cursor. For a podcast with no episode under the
    cursor, pine shows the error `select an episode to see its listening
    sessions`.
  * On a different screen, `R` shows the sessions of the item that plays. If
    no item plays, `R` shows the sessions of all items.
* **The command palette has two new entries.** "Listening History" shows the
  sessions of all items. "Listening Sessions", in the context actions of the
  detail screen, shows the sessions of the book or of the episode under the
  cursor.
* **A row shows where a session ended.** A row for one item shows the end
  position, the start position, the device, the client, the time of the last
  sync, and the listening time. A row for all items starts with the book and
  its author, or with the podcast and the episode. "(this device)" marks a
  session of this pine.
* **Enter plays from the end of the session.** If the item of the session
  plays, pine seeks to that position. If not, pine stops the current playback
  and starts the item of the session at that position. The next sync sends
  the position to the server.
* The screen shows the 50 newest sessions. `/` filters the list, and `H` and
  `L` move one page.

### Reliability and Correctness

Cache:

* **A failed cache write stopped a request that the server answered.** pine
  wrote the answer of the server to its cache, and then read the answer back
  from the cache. If the write failed, pine showed `unexpected cache miss
  after fetch for key …` and did not use the answer. A screen did not load,
  or the session restore did not start. pine now uses the answer of the
  server, and writes a cache error to the log as a warning.
* **Two writes to the database at the same time failed.** SQLite allows one
  write at a time, and pine did not wait for the lock. The second write
  failed with `database is locked (5) (SQLITE_BUSY)`. This was the usual cause
  of the error above. It also stopped the local save of the last session at
  times. A write now waits up to 5 seconds for the lock.
* **A database error of the cache did not show in the log.** pine read it as
  a missing value. pine now writes the error to the log.

### Changes of Behavior

* Each cache key in the database has a version. After the upgrade, pine does
  not read the cache of an older pine. At the first start, pine gets each
  value from the server again, and it builds the search index of each library
  again. pine deletes the old rows after they expire, during playback.
* On an empty cache, pine can get the first page of a library from the server
  two times: one time for the library screen and one time for the search
  index. Before, pine sent one request for both.

## spruce

spruce has no change in this release. The shared package
`internal/ui/components` has one new palette action, which only pine uses.

## Development

* `R`, the palette entries, and Enter on a session have tests that use a fake
  Audiobookshelf server and the mock player of the app tests.
* The listening sessions ran against grove-server, which implements the API
  of Audiobookshelf 2.37.1. pine showed the 50 newest of 955 sessions, and
  the sessions of one episode, with the values of the server. Enter on a
  session ran only in the tests.
* No check ran against a real Audiobookshelf server. The routes
  `GET /api/me/listening-sessions` and
  `GET /api/me/item/listening-sessions/{id}/{episodeId}` are in the source of
  Audiobookshelf 2.37.1.
* Each cache correction has a test that failed before the correction. A
  manual test held the write lock of the database with `sqlite3`. v0.8.3
  showed `unexpected cache miss`, and the new code showed the detail screen.
* `internal/cache` has a smaller design. Each cached method calls one helper,
  `cached(c, key, ttl, fetch)`. `internal/cache/keys.go` has the name of each
  cache key, and the app uses these names. The package has 289 lines of
  production code, and had 687.

## Requirements

- Go 1.26.4 or newer, for an installation from source
- libmpv from [mpv](https://mpv.io/) 0.34 or later
- pine: an [Audiobookshelf](https://www.audiobookshelf.org/) server
- spruce: a [Jellyfin](https://jellyfin.org/) account with a music library
