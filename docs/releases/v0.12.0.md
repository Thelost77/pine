# pine and spruce v0.12.0

This release makes pine stop the playback before the system sleeps, so that
pine is silent after the wake and does not replace newer progress from another
device. The home screen of pine now shows the last shelves at once, and then
loads them again from the server. spruce has no change.

## Installation

```sh
go install github.com/Thelost77/pine@v0.12.0
go install github.com/Thelost77/pine/cmd/spruce@v0.12.0
```

As an alternative, download an archive from the release page. See "Binaries".

## Binaries

The release has one archive for each program and each system. The name of an
archive is `<program>_v0.12.0_<system>_<architecture>`:

| System | Architecture | File type |
|--------|--------------|-----------|
| `linux` | `amd64`, `arm64` | `.tar.gz` |
| `darwin` (macOS) | `amd64`, `arm64` | `.tar.gz` |
| `windows` | `amd64` | `.zip` |

Each archive contains the program, the `LICENSE` file of pine, and a `licenses`
directory. That directory has the license texts of Go and of the modules that
the program links.

- A binary needs libmpv. See "Requirements".
- On Windows, put `libmpv-2.dll` in the directory of the program. The archive
  does not contain it.
- The binaries are not signed.
- A GitHub Actions workflow builds the binaries on Linux with `CGO_ENABLED=0`.
  No binary of this release has run on a test machine.

## pine

### New Features

* **pine stops the playback before the system sleeps.** This is for Linux
  with logind. pine holds a sleep delay inhibitor of logind. Before a suspend
  or a hibernation, pine sends the position, closes the session, and stops
  mpv. pine holds logind back for 10 s at most. logind can have a shorter
  limit (`InhibitDelayMaxSec`). Before, mpv played on
  after the wake, and the next sync sent the old position to the server. The
  server saves a sync with no time check, so that sync replaced newer progress
  from another device.
* **After the wake, pine stays stopped.** Start the book again. The new play
  session starts at the position of the server, so progress from another
  device stays.
* **The home screen shows the last shelves at once.** At the start and at a
  change of the library with `tab`, pine shows the shelves from its local
  cache, also when they are old. Then it loads them from the server and
  replaces them. Before, the home screen showed loading rows until the server
  answered.
* **The home screen keeps its shelves when the server does not answer.** The
  error goes to the log, and the shelves stay. Before, the error text replaced
  the shelves.

### Fixes

* **A 401 from the load of the home screen now opens the login screen.**
  Before, the home screen showed the error text, and pine stayed on the home
  screen with an expired sign-in.

### Limits

* The stop before a sleep needs Linux with logind and a system bus. On macOS
  and on Windows, pine runs as before and writes "system sleep monitor is off"
  to the log.
* pine tries to send the position before the sleep, but the network can go
  down first. On the test machine, NetworkManager disconnected the Wi-Fi 74 ms
  after the sleep signal. If the request fails, the progress since the last
  sync is lost. pine sends the progress every 30 s.
* The old shelves show the old progress until the server answers. The
  playback does not use it: it starts at the position of the server.
* pine keeps an expired cache entry for 30 days, so that a start can show it.
  pine does not show an older entry.
* When the server does not answer and the home screen shows shelves, pine
  shows no error on the home screen. The error is in the log.

## spruce

spruce has no change in this release. No shared package changed.

## Development

* The changes are in
  [pull request 19, "Stop the playback before the system sleeps, and show the cached home shelves at once"](https://github.com/Thelost77/pine/pull/19).
  A comparison of pine with [Spotifast](https://github.com/crmne/spotifast)
  found the two changes.
* The new package `internal/systemsleep` holds the inhibitor. It is a pine
  package, and `scripts/release.sh` checks that spruce does not link it.
* A code review of the pull request found eight defects in the new code. Each
  defect has its own commit and a test that failed before the fix.
* The sleep tests use a fake logind on a private D-Bus bus. A program ran the
  package against the logind of a Linux machine, and `systemd-inhibit --list`
  showed the inhibitor. A real suspend with pine playing was not tested.
* The statement about the sync comes from the source of Audiobookshelf 2.37.1:
  `server/managers/PlaybackSessionManager.js`, function `syncSession`.
* On Linux, `gofmt`, `go vet` (also for macOS and Windows), `golangci-lint`
  2.14.0, and the tests with `PINE_REQUIRE_LIBMPV=1` and `PINE_REQUIRE_DBUS=1`,
  also with `-race`, passed. The CI workflow passed for the pull request on
  Ubuntu, macOS, and Windows.
* The dependencies have no change. `github.com/godbus/dbus/v5` was already a
  dependency for MPRIS.

## Requirements

- Go 1.26.4 or newer, for an installation from source
- libmpv from [mpv](https://mpv.io/) 0.34 or later
- pine: an [Audiobookshelf](https://www.audiobookshelf.org/) server
- spruce: a [Jellyfin](https://jellyfin.org/) account with a music library
