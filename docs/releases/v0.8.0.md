# pine and spruce v0.8.0

Each release now has binaries for Linux, macOS, and Windows. pine and spruce
also have an MPRIS server of their own. It replaces a module with a GPL-3.0
license. All the code in the two programs now has a permissive license.

## Installation

```sh
go install github.com/Thelost77/pine@v0.8.0
go install github.com/Thelost77/pine/cmd/spruce@v0.8.0
```

As an alternative, download an archive from the release page. See "Binaries".

## Binaries

The release has one archive for each program and each system. The name of an
archive is `<program>_v0.8.0_<system>_<architecture>`:

| System | Architecture | File type |
|--------|--------------|-----------|
| `linux` | `amd64`, `arm64` | `.tar.gz` |
| `darwin` (macOS) | `amd64`, `arm64` | `.tar.gz` |
| `windows` | `amd64` | `.zip` |

Each archive contains the program, the `LICENSE` file of pine, and a `licenses`
directory. That directory has the license texts of Go and of the modules that
the program links.

- A binary needs libmpv. See "Requirements".
- On Windows, put `libmpv-2.dll` in the directory of the program. The archive
  does not contain it.
- The binaries are not signed.
- A GitHub Actions workflow builds the binaries on Linux with `CGO_ENABLED=0`.
  The binaries for `linux_arm64`, macOS, and Windows have not run on a test
  machine.

## Licenses

pine and spruce have the MIT license. From v0.8.0, each module that the two
programs link has an MIT, BSD, or Apache-2.0 license.

Versions v0.2.0 to v0.7.0 link the module
`github.com/quarckster/go-mpris-server`, which has the GPL-3.0 license. spruce
v0.1.0 and v0.2.0 from its old repository link it too. If you distribute a
binary of one of these versions, the GPL-3.0 applies to that binary. These
versions have no binaries on the release page.

## pine and spruce

### What's New

* **Binaries on the release page:** an installation does not need Go.
* **An MPRIS server of our own:** the server is written from the MPRIS 2.2
  specification. It uses `godbus/dbus` and no other module.

### Reliability and Correctness

* A D-Bus client that set `Volume` to a value of a wrong type stopped the
  program. The server now returns an error.
* The MPRIS metadata contains only the fields that have a value. Before, it
  contained 22 fields, and most of them were empty.
* The introspection data shows only the interfaces that the programs have.
  Before, it also showed `TrackList` and `Playlists`.
* The `PropertiesChanged` signal does not contain `Position` or `CanControl`.
  The MPRIS specification excludes them from that signal.

## Platforms

* **Linux:** pine was tested with the buttons of Bluetooth headphones, through
  BlueZ 5.72 and `mpris-proxy`.
* BlueZ gives the headphone buttons to the first MPRIS player on the session
  bus. If a browser plays media before pine or spruce starts, the buttons
  control the browser. This is the behavior of BlueZ. pine and spruce cannot
  change it.

## Development

* The `Release` workflow builds the archives when a GitHub Release is
  published.
* A new test starts the MPRIS server on a private D-Bus session bus and checks
  it as an MPRIS client does. With `PINE_REQUIRE_DBUS=1`, the test fails if
  `dbus-daemon` is absent. Without the variable, the test skips.

## Requirements

- Go 1.26.4 or newer, for an installation from source
- libmpv from [mpv](https://mpv.io/) 0.34 or later
- pine: an [Audiobookshelf](https://www.audiobookshelf.org/) server
- spruce: a [Jellyfin](https://jellyfin.org/) account with a music library
